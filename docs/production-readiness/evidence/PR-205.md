# PR-205 — Stale-success elimination

Status: **VERIFIED**

## Implemented

- `lib.output_promotion.promote_candidate` fingerprints the candidate before
  probing and requires its filesystem timestamp to be after the durable
  run/attempt start when that evidence is available.
- Promotion re-fingerprints the adopted final after `os.replace`, verifies the
  digest is unchanged, and records hash, size, candidate/output timestamps, and
  the run-start freshness proof in the promotion result.
- Work-order claims persist `metadata.attempt_started_at`; compose promotion
  reads that timestamp from the run record and passes it to the freshness gate.
- Legacy/internal runner checks no longer accept `final.mp4` when the current
  renderer reports failure.
- The render-report contract accepts current-output SHA-256 and freshness
  evidence so an agent can submit durable proof with the compose checkpoint.
