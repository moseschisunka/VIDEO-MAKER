# PR-1026 — Enforce strict audio-mixer controls

Status: `IMPLEMENTED` locally; supported CI verification remains required.

## Finding

`AudioMixer` accepted malformed boolean controls through Python truthiness.
Values such as `"false"`, `0`, `1`, or `null` could silently change whether
normalization, independent stem preservation, quality checks, or music ducking
ran. That makes the delivered audio differ from the authored design and can
hide a failed quality check behind a successful-looking result.

## Remediation

- Require real booleans for `normalize`, `preserve_stems`, and `quality_check`.
- Require `ducking` to be a boolean or object and reject malformed
  `ducking.enabled` values before any FFmpeg process starts.
- Preserve the existing explicit loudness-target clamping contract and all
  valid legacy defaults.
- Add regression coverage for string, integer, null, and collection values.
