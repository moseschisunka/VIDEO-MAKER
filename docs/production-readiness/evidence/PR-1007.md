# PR-1007 — Define and measure SLOs

## Status

**VERIFIED** for the offline SLO contract and the supported Ubuntu reference
baseline. This does not close the bounded load/soak gates, live-provider SLOs, human
audiovisual quality review, or the global production decision. Production
remains ineligible until `PR-11G` passes.

## Implementation

- Added [`lib/slo.py`](../../../lib/slo.py), the single implementation for
  loading/validating the SLO contract, deterministic p50/p95 summaries,
  latency threshold evaluation, ratio/error-budget evaluation, and monotonic
  callback measurement.
- Added [`config/slo.yaml`](../../../config/slo.yaml), fixing targets and
  measurement boundaries for `PERF-01` through `PERF-10` plus availability,
  queue-start, recovery, local-render, and zero-tolerance quality-escape SLOs.
- Added [`docs/operations/SLOs.md`](../../operations/SLOs.md), including the
  reference environment, sample policy, alert thresholds, error budgets,
  exclusions, and operator measurement procedure.
- Added [`scripts/measure_slos.py`](../../../scripts/measure_slos.py) and a
  `make slo` entry point. The command is offline-only and emits JSON with the
  observed environment and raw summary values.
- Added release-blocking coverage in
  [`tests/contracts/test_phase10_slos.py`](../../../tests/contracts/test_phase10_slos.py).
- Cached the release-aware pipeline catalog by manifest fingerprint. This
  removes repeated manifest/skill/schema validation from warm create-request
  validation while returning defensive copies to callers.
- Linked the SLO contract and measurement command from
  [`config/observability.yaml`](../../../config/observability.yaml); the
  bounded metrics endpoint remains a diagnostic snapshot and not a monthly
  denominator.
- Changed the FFmpeg compose default from `medium` to the explicit `fast`
  preset while retaining CRF quality and honoring caller overrides. This
  removes the observed Windows interactive-render SLO miss without weakening
  the `PERF-06` target.

## Supported Ubuntu reference run

GitHub Actions run `33710765514` executed the documented reference procedure
on Ubuntu 24.04 with Python 3.11, Node 22, the apt FFmpeg/ffprobe pair, and a
2-vCPU/7-GB runner. All seven measured SLOs passed their 11-sample p95
thresholds: provider menu **0.019s / 2.0s**, fast preflight **0.000126s /
5.0s**, create validation **0.059s / 0.5s**, state refresh **0.0034s / 0.4s**,
duplicate-run response **0.154s / 0.5s**, local render **1.127x / 2.0x**, and
restart/resume detection **0.268s / 0.5s**. The raw machine-readable result
is committed above; the run used only local/fake providers and no paid calls.

`PERF-08`, `PERF-09`, and `PERF-10` have fixed targets but remain owned by
`PR-1009` because they require bounded concurrency and soak evidence. No live
provider latency or quality-escape rate is inferred from this offline run.

## Decision and next task

The 500 ms create-validation target initially failed on the uncached catalog
(approximately 0.97 s p95 on this workstation). Fingerprint-based catalog
caching reduced the measured p95 below target. A later Windows diagnostic
also exceeded `PERF-06` before the compose preset was tuned; the post-tuning
11-sample Windows diagnostic passes at 1.005x, and the supported Ubuntu
reference now passes at 1.127x. This closes the SLO-reference portion of
`PR-10G`; external monitoring, trusted-edge security, and deployment rollback
proof remain separate blockers.
