# PR-1018 — Align Backlot visual fixtures with immutable approvals

Status: `IMPLEMENTED` (local regression and adjacent gates pass; supported CI
verification pending publication)

## Finding

The canonical Backlot screenshot-stage, simulation, and quarantined internal
demo runner still completed manifest-gated stages by passing the deprecated
mutable `human_approved=True` bit. The current checkpoint contract correctly
rejects that write, so the fixtures could not stage or simulate a complete run
even though the production approval endpoint already requires an immutable
approval record. The internal runner also passed stale `locale`/`settings`
arguments to `init_project`, which would fail before rendering. These were
test/diagnostic reliability defects: they could block visual review and give a
false impression that the board or pipeline had failed.

## Remediation

- All three fixture paths now create/use a UUIDv4 `run_id` and use the same
  `awaiting_human` → immutable approval → `completed` transition as Backlot.
- The synthetic approval is built from the pending checkpoint and remains bound
  to its exact artifact digest and timestamp; the completion preserves that
  artifact version and cost snapshot.
- The internal demo runner now calls the canonical `init_project` signature and
  leaves ungated edit/compose checkpoints free of misleading approval bits.
- New release-blocking contracts verify approval-log counts, UUID identity,
  gated/awaiting state, and the simulation/internal-runner approval records.

deployment, external metrics or paging sink, trusted-edge enforcement, live
providers, human audiovisual review, canaries, or the final `PR-11G` gate.
