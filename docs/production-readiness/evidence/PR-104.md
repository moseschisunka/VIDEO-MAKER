## Implemented contract

`schemas/work_orders/work_order.schema.json` and `lib/work_order.py` now define
the deterministic control-plane envelope created after request validation and
before an agent/run starts. The initial order records:

- immutable project/title/topic identity and selected pipeline;
- exact manifest version and SHA-256 bytes hash;
- UUIDv4 run identity and attempt number;
- manifest-derived contiguous stage order with ready/pending state;
- current and next stage plus a resumable next action;
- playbook, voice/provider, renderer, profile, aspect-ratio, and source-mode
  selections;
- explicit proposal approval record/reference;
- claim owner, lease expiry, heartbeat, and lease version fields;
- last successful checkpoint/resume pointer; and
- structured blocker/error state.

`build_work_order()` is pure apart from reading the manifest bytes. It does not
create a directory, contact a provider, or launch a renderer. `write_work_order`
validates the envelope and atomically replaces `work_order.json` under an
already-created project. Backlot creates this file before the remaining project
scaffold and returns the same run envelope to the caller. Board state exposes
the persisted control-plane record read-only and includes it in activity timing.

The validator rejects schema violations, manifest identity/hash drift,
duplicate or non-contiguous stages, and completed-stage skips. This establishes
the invariants that PR-108 will use for claims, legal advances, and resume.
