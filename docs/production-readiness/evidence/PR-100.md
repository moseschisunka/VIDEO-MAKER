## Implemented contract

`schemas/pipelines/pipeline_manifest.schema.json` now defines the following
optional release metadata fields:

- `ui_visible` (default annotation `false`);
- `maturity` (`test`, `experimental`, `beta`, or `production`; default
  annotation `experimental`);
- `supported_runtimes`;
- `supported_profiles`;
- `required_capabilities`;
- `required_artifacts`;
- `deprecated`, `replacement_pipeline`, and `deprecation_reason`.

`lib.pipeline_loader.get_manifest_release_metadata()` supplies effective values
without mutating the loaded manifest. JSON Schema defaults alone do not mutate
YAML data, so the helper explicitly fails closed: missing or invalid maturity
is `experimental`, missing visibility is hidden, and missing capability/runtime,
profile, and artifact lists are empty.

Backlot's PR‑003 release helper consumes these effective values as descriptive
manifest metadata, while the separately approved Phase 0 scope remains the
authority for user-facing availability. A manifest's legacy `stability:
production` field cannot bypass the `PR-11G` production lock.
