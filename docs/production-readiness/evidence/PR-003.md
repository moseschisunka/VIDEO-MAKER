# PR-003 — Honest non-production labelling

**Date:** 2026-09-02
**Task status:** `VERIFIED` — release labels and scope enforcement are wired through Backlot
**Owner:** OpenMontage execution agent
**Depends on:** `PR-002` (`COMPLETE`, Option A approved)
**Production gate:** `PR-11G` (still not passed)

## Implemented controls

- Added the reviewed, versioned scope decision at
  [`config/pipeline_release_scope.json`](../../../config/pipeline_release_scope.json).
  It covers all 13 manifests, keeps `screen-demo` and source-footage
  `talking-head` as launch candidates, holds the other workflows in beta or
  experimental lanes, and keeps `framework-smoke` test-only.
- Added [`lib/pipeline_release.py`](../../../lib/pipeline_release.py), a
  fail-closed metadata helper. A manifest's declared `stability` is descriptive;
  it cannot make a pipeline production-ready. Missing scope, malformed scope,
  schema-invalid manifests, and test-only workflows are never creatable.
- Changed Backlot pipeline discovery to use
  `lib.pipeline_loader.load_pipeline_readonly` and to expose schema validity,
  release lane, availability, creation permission, release status, and the
  mandatory `PR-11G` production gate. `framework-smoke` is omitted from
  user-facing discovery; `documentary-montage` was initially hidden while its
  schema was invalid and is now discoverable only as an explicitly held,
  non-creatable experimental lane after PR-101 repaired its category.
- Added `/api/release-status` and release fields to project summaries, board
  state, project creation responses, and the persisted project marker. Every
  surface explicitly reports `production_ready: false` and
  `release_status: not_certified`.
- Updated the library and board UI with an internal-preview banner, per-pipeline
  lane labels, disabled held-lane selection cards, an uncertified rendered-output
  label, and an internal-preview creation action. The wizard defaults to the
  approved `screen-demo` launch candidate.
- Direct create requests for held, hidden, test-only, or unclassified pipelines
  return HTTP 400 before any project directory is created.

## Acceptance decision

`PR-003` is verified. The user-facing Studio and API now make the current state
unambiguously internal preview/non-production, hide test-only and malformed
workflows, and enforce the approved launch boundary before mutation. This is a
release-control improvement, not a certification of either launch candidate.
`PR-0G` may proceed to its evidence gate, while production remains ineligible
until every roadmap gate through `PR-11G` passes.
