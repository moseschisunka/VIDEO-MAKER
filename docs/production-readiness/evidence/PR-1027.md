# PR-1027 — Fail closed on green-screen frame loss

Status: `IMPLEMENTED` locally; supported CI verification remains required.

## Finding

`GreenScreenProcessor` could report success after a failed FFmpeg frame
extraction if any partial PNGs remained, and both frame-processing methods
returned success when only one frame had been processed. The reconstruction
step could therefore emit a shortened or visually incomplete video. The
chromakey retry path also constructed a compositing command but never ran it;
its key-only fallback could silently discard the requested background color.

## Remediation

- Treat any non-zero/raised extraction command, missing frame, or non-contiguous
  frame sequence as a failed extraction; partial frames are never reconstructed.
- Require every extracted frame to produce a non-empty processed frame for both
  chromakey and rembg paths.
- Execute only a background-preserving chromakey retry; do not accept a
  key-only fallback that changes the authored visual contract.
- Validate positive input media facts, supported method/fps/frame-limit inputs,
  non-empty processed output, and output dimensions/duration through FFprobe.
- Reconstruct into a UUID-scoped candidate and atomically promote it only after
  validation, preserving any previous final when the new encode fails.
- Declare FFprobe alongside FFmpeg as a runtime dependency.
