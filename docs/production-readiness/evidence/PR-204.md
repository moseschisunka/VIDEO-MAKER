# PR-204 — Atomic output promotion

**Date:** 2026-09-02

**Next task:** `PR-205` — eliminate stale-success logic

## Goal

Prevent a failed or malformed current render from claiming an old
`renders/final.mp4`. Renderers must produce a run-scoped candidate, probe it,
and only then atomically promote it to the canonical deliverable.

## Implementation

- Added `lib/output_promotion.py` with unique candidate naming, ffprobe-backed
  container/stream/duration/dimension/fps inspection, SHA-256 calculation, and
  same-volume `os.replace` promotion.
- A candidate is validated against the selected media profile and optional
  expected duration before any canonical final is touched. Existing finals are
  therefore preserved when probing or contract validation fails.
- FFmpeg composition, normal Remotion rendering, HyperFrames rendering, and
  the high-level runtime path now use run candidates for durable projects and
  return canonical output paths only after promotion. Direct legacy calls keep
  their compatibility behavior.
- Promotion metadata includes candidate/final paths, digest, byte size,
  normalized media facts, and project/run/stage/tool provenance for later
  render-report and run-record reconciliation.
- Remotion/HyperFrames failures remove only their resolved run candidate;
  unrelated projects and prior finals are outside the cleanup boundary.
