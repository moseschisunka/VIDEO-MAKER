# PR-302 — Idempotency keys and result cache

Status: **VERIFIED**

Provider requests use a stable SHA-256 key incorporating the provider/model,
capability/operation, complete serialized creative payload, legacy tool key,
and run identity. Successful results are written atomically to a cache and are
revalidated (including local artifact existence, size, and hash) before reuse.
The bridge scopes production caches to the project provider-cache directory.

Evidence:

```text
python -m pytest -q tests/contracts/test_phase3_provider_executor.py tests/contracts/test_phase3_provider_migration.py
11 passed in 0.21s
```

The tests prove a replay and a new executor process return `cached` without
reinvoking the provider.
