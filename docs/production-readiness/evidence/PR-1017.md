# PR-1017 — Fail-closed media timeline and stream validation

Status: `IMPLEMENTED` (local regression and adjacent gates pass; supported CI
verification pending publication)

## Finding

The Phase 6 ingestion boundary treated any ffprobe-readable audio/video
container as usable when it contained a stream, even if the reported duration
was `0`, `N/A`, `NaN`, or otherwise non-positive. It also did not verify that a
declared `audio`/`video` media type had a matching stream. Such input could
reach stock, user-media, or generated-asset manifests and fail later during
timeline planning or composition.

The regression set reproduces zero, non-finite, and negative durations with a
recognized ISO-BMFF header and ffprobe responses containing a video stream;
before the fix, the zero-duration case did not raise `MediaValidationError`.

## Remediation

- `validate_media_file()` now requires a list of decoded streams and checks the
  expected audio/video stream type for declared audio/video/animation/stock
  inputs.
- It parses finite positive duration from the container or a stream-level
  duration when the container omits it, and rejects an input when no positive
  duration exists.
- The guard remains inside the existing fail-closed ingestion path, so callers
  still receive the same `MediaValidationError` boundary and partial download
  cleanup behavior.
