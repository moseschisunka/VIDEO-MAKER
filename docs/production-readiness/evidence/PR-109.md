## Goal

Prove one deliberately supported launch-candidate pipeline can travel from a
durable work order through agent-authored artifacts, a real human gate, the
manifest-selected renderer, current-run output review, and publish without the
legacy generic runner inventing stage output.

## Implemented contract

`lib.manifest_executor` is the agent-first handoff boundary. It reads the
manifest-derived next stage, validates the stage director contract and all
required input artifacts, rejects undeclared or schema-invalid output, checks
critical local media references for project confinement/existence, writes
artifacts/checkpoints atomically, and advances only through
`lib.work_order.advance_work_order`. In-progress submissions remain resumable;
human-gated submissions pause until the approval path explicitly releases
them. The module has no provider calls and makes no creative decisions.

Backlot now exposes read-only execution context and an agent stage-submission
route. Ordinary `/run` for the certified `screen-demo` lane claims the durable
work order and returns the director skill/context; it does not spawn
`lib.project_pipeline`. The old process remains reachable only for an explicit
internal-demo marker.

The render boundary now resolves canonical project-relative asset, audio,
subtitle, transcript, and script paths against the current project rather than
the process working directory. This prevents a same-named file in another
working directory from being rendered or a valid project asset from being
reported missing. The normalized manifest view is passed consistently to
FFmpeg, Remotion, and HyperFrames adapters.

## Residual risks

This certifies one local screen-demo path, not every advertised pipeline,
provider, voice, runtime, format, or deployment mode. Remotion and HyperFrames
still require their later runtime gates; stale-output prevention, run-scoped
staging, provider execution, factual grounding, voice verification, and
operational certification remain open. The known provider-catalog drift is
still routed to `PR-300`/`PR-306`/`PR-309`. Production cannot be declared until
`PR-11G` passes.

## Rollback

Revert the manifest executor/API/test changes and remove the certified executor
allow-list entry only as one reviewed change. Preserve existing project
directories and work orders; resume or migrate them through a schema-aware
operation rather than deleting state.
