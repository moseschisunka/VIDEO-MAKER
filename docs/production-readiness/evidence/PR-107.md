## Implemented contract

`lib.project_identity` now provides a read-only cross-artifact identity
report and strict assertion boundary. It establishes the project identity from
the directory and durable work order, then checks the marker, work order,
project config, proposal (including `production_plan.pipeline`), decision logs,
current/history checkpoints, render report, and valid event records. Missing or
mismatched `project_id`, `pipeline_type`, or `run_id` is reported as a
structured issue; malformed append-only event lines remain warnings so a torn
telemetry write cannot hide valid neighboring events.

The artifact contracts now allow explicit identity fields in proposal packets,
decision logs, render reports, and checkpoints. Checkpoint writes backfill the
run ID from the work order/marker and fail closed when a cumulative decision
log attempts to change project, pipeline, or run identity. Event instrumentation
backfills missing identity from the same durable sources without overriding an
explicit caller value.

The internal demo runner no longer hardcodes `animated-explainer` or `remotion`
in its proposal. It reads the configured pipeline/runtime and propagates the
stable run ID through proposal, decision log, edit metadata, render report,
checkpoints, and events. Backlot creation and visual variants perform a
read-only identity check before returning success, and board state exposes the
identity report for inspection.
