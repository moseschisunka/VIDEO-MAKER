# PR-203 — Per-run staging isolation

**Date:** 2026-09-02
**Task status:** `VERIFIED`
**Owner:** OpenMontage execution agent
**Depends on:** `PR-201` (`VERIFIED`)
**Next task:** `PR-204` — publish outputs atomically

## Goal

Ensure renderer scratch state is scoped to the immutable project/run identity.
Concurrent projects must not share Remotion public assets, props, FFmpeg temp
segments, or HyperFrames workspaces.

## Implementation

- Added `RunPaths` and UUIDv4 validation in `lib/paths.py`, creating the
  bounded `runs/<run-id>/{work,inputs,props,logs,candidates,reports}` layout.
  Symlink escapes and traversal-shaped run IDs fail closed.
- VideoCompose resolves relative output paths against the current project and
  derives the run envelope from the explicit/work-order identity.
- FFmpeg segment/concat scratch directories use unique children under the run's
  `work/` directory and are removed after the operation.
- Normal Remotion renders stage assets into a unique run `inputs/` public
  directory and persist props under run `props/`; legacy direct calls retain a
  compatibility scratch path. Staged names are indexed to prevent same-basename
  asset collisions.
- HyperFrames render workspaces default to run `work/hyperframes/` for durable
  runs, and the atelier path uses a run-specific source staging namespace.
- Renderer result metadata reports the run directory and staging paths for
  inspection; canonical final-output promotion remains the explicit `PR-204`
  responsibility.

## Residual risks

The final MP4 is still written to the caller's canonical output path after a
successful renderer call. Validated candidate promotion, stale-output proof,
and failure-safe preservation of a prior final are the next `PR-204`/`PR-205`
tasks. HyperFrames' full CLI/network-backed suite remains an environment
diagnostic rather than a certification gate here. Production remains locked
until `PR-11G`.

## Rollback

Revert `RunPaths` and the renderer staging hooks as one reviewed change. Keep
run directories and their props/logs intact for forensic inspection; do not
delete them as part of rollback.
