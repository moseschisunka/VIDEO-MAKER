# PR-1036 — Enforce strict manifest approval persistence

Status: `IMPLEMENTED` locally; supported CI verification remains required.

## Finding

The manifest handoff and checkpoint writer accepted non-boolean
`human_approved`/`human_approval_required` values. A direct caller could pass
`"false"` or `1`, and Python truthiness would persist a misleading approval or
gate state. The Backlot request model also used coercible `bool` parsing.

## Remediation

- Reject malformed approval flags before manifest state is loaded or mutated.
- Apply the same strict type contract at checkpoint persistence.
- Use Pydantic `StrictBool` for the Backlot stage request while retaining the
  direct-call guard in the manifest executor.

## Local verification

The focused approval-boundary suite, Phase 9 approval contracts, and Backlot
checkpoint contracts pass **45 tests**. No provider credentials, network
calls, or paid generation were used. The full local release/offline matrices
and supported CI verification remain required before this checkpoint is
verified.

## Residual scope and rollback

This closes approval-value coercion at the durable handoff boundary. It does
not replace immutable human approval records, deployment/rollback proof,
trusted-edge evidence, external observability, or `PR-11G`. Revert only with
the strict-boundary tests and historical evidence retained.
