# PR-202 — Idempotent `/run`

**Date:** 2026-09-02
**Task status:** `VERIFIED`
**Owner:** OpenMontage execution agent
**Depends on:** `PR-201` (`VERIFIED`)
**Next task:** `PR-203` — isolate per-run staging

## Goal

Make Backlot's manifest-agent `/run` request safe to retry. A repeated request
must observe the existing active run rather than create a second process, run,
or lease owner.

## Implementation

The ordinary `/api/project/{project_id}/run` path now keeps the durable work
order as the idempotency source of truth:

- A same-agent retry renews the existing lease without incrementing its lease
  version and returns `idempotent_replay: true`.
- A different caller that races with or encounters a live lease receives the
  existing run read-only, including the actual owner and requested caller,
  rather than a second claim or process.
- The conflict path re-reads and validates the work order after the atomic
  claim conflict, so an expired or terminal run cannot be reported as active.
- The quarantined legacy runner remains unreachable for ordinary projects.

## Residual risks

This protects the request/claim boundary, not yet renderer output reuse or
paid-provider replay. Per-run work/props/candidate isolation and atomic output
promotion remain open in `PR-203`/`PR-204`; restart/cancellation semantics are
`PR-206`. Production remains locked until `PR-11G`.

## Rollback

Revert the `/run` conflict-reconciliation branch and its contract test as one
reviewed change. Keep the durable work-order/run-record state intact so a
future retry can still inspect the current owner and lease.
