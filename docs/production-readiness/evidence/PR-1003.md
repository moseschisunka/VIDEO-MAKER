# PR-1003 — Harden container/deployment build

## Status

**IMPLEMENTED — CI container execution still required for verification.**

Production remains ineligible until the complete roadmap, including `PR-11G`,
passes. This task is not marked `VERIFIED` locally because the workstation
does not have a Docker daemon or Docker CLI available.

## Changes

- Replaced the unpinned runtime image with the multi-architecture
  `node:22.13.1-bookworm` image pinned to manifest digest
  `sha256:5145c882f9e32f07dd7593962045d97f221d57a1b609f5bf7a807eb89deff9d6`.
- Installed only the required OS runtime packages (Python, pip, and FFmpeg),
  installed the local Python distribution, ran `npm ci` against the committed
  Remotion lockfile, and baked the pinned Remotion browser into the image with
  `npx --no-install remotion browser ensure`.
- Ran the container as the non-root `node` user, exposed only the documented
  Backlot port, declared project/output volumes, and added a liveness
  `HEALTHCHECK` that forwards the runtime bearer token when configured.
- Hardened Compose with loopback-only publishing by default, read-only root
  filesystem, scoped writable volumes/tmpfs, dropped Linux capabilities,
  `no-new-privileges`, restart policy, and the same token-aware health check.
- Expanded `.dockerignore` to exclude credentials, private keys, local output,
  caches, temporary fixtures, and dependency/build directories.
- Added a CI `container-build` release-blocker job that builds the image,
  checks the non-root user and healthcheck, starts it with a read-only/tmpfs/
  capability-dropped policy, waits for an authenticated healthy endpoint, and
  renders the asset-free/default-preview `EndTag`, `ProductReveal`,
  `SignalFromTomorrowWithMusic`, `TalkingHead`, `TitledVideo`, and
  `LyricOverlay` compositions inside the image with the baked Remotion
  browser. The job retains a small JSON render-evidence artifact.
