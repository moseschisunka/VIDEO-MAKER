# PR-1028 — Enforce VideoSelector motion and validation controls

Status: `IMPLEMENTED` locally; supported CI verification remains required.

## Finding

`VideoSelector` declared `motion_required`, `strict_media_validation`, and
`production_mode` as booleans but used Python truthiness at the generation
boundary. A malformed value such as `"false"` or `1` could silently change the
quality-gate path. A text-to-video request with an explicit motion requirement
could also retain `image_selector` as a fallback and accept a still downgrade.
Unknown operations were allowed to reach provider selection instead of failing
at the API boundary.

## Remediation

- Validate all three generation policy controls with the shared strict-boolean
  contract before any provider executor call.
- Carry the validated motion requirement into output validation and reject
  image/still downgrades for every motion-required operation, including an
  explicit requirement on a text-to-video brief.
- Remove the image-only fallback whenever motion is required; malformed motion
  values are handled conservatively by the read-only fallback helper and fail
  with a typed error in `execute()`.
- Reject operations outside the supported text/image/reference-to-video set
  before provider selection.

## Residual scope

This closes selector policy coercion, still downgrade, and operation-boundary
defects. It does not resolve the Windows-vs-reference SLO variance, certify live
providers, external observability or paging delivery, trusted-edge enforcement,
deployment rollback, human audiovisual review, frozen release-candidate
evidence, or `PR-11G`.

## Rollback

Revert commit `a892a2b` only after preserving this finding and its tests. Do not
restore truthy quality-gate controls or image fallbacks for motion-required
briefs in a production selector.
