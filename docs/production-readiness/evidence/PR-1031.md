# PR-1031 — Enforce strict TTS batch approval controls

Status: `IMPLEMENTED` locally; supported CI verification remains required.

## Finding

The TTS selector accepted truthy values for `batch`, `sample_mode`, and
`timestamps`. In particular, a transport value such as `"false"` could alter
the batch/sample approval path and reach voice-provider selection.

## Remediation

- Parse the three public controls as real booleans before voice identity,
  provider discovery, or generation work.
- Keep sample-mode approval from bypassing a required batch approval.
- Reject unsupported operations and non-array batch segments at the selector
  boundary.

## Local verification

The focused TTS/provider contract suite passes **75 tests**. The final local
checkpoint matrix containing this change is recorded in the tracker; supported
CI must rerun the complete release and offline suites before verification.

No provider credentials, network calls, or paid generation were used.

## Residual scope and rollback

This closes TTS selector coercion and batch-gate bypasses. It does not certify a
live provider, audiovisual review, deployment, or `PR-11G`. Revert the
containing commit only with the regression suite and approval evidence kept.
