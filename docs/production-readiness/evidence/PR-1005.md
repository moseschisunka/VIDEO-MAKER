# PR-1005 — Define secrets, privacy, retention, and deletion policy

## Status

**VERIFIED** for the documented policy and local redaction contracts. Automated
purge and recovery remain later Phase 10 work; production remains ineligible
until `PR-11G` passes.

## Changes

- Added the machine-readable [`config/security_policy.yaml`](../../../config/security_policy.yaml)
  contract for remote authentication, project scope, path confinement, secret
  handling, retention defaults, deletion safeguards, and provider disclosure.
- Added the operator-facing
  [`docs/operations/SECRETS_PRIVACY_RETENTION.md`](../../operations/SECRETS_PRIVACY_RETENTION.md)
  policy. It distinguishes local processing from external provider transfer,
  requires consent/approval for user media leaving the runtime, records the
  provider/model/data class/terms reference, and does not promise provider-side
  retention or deletion behavior.
- Added explicit Backlot and retention placeholders to `.env.example`; real
  credentials remain runtime-only and `.env` is ignored by Git and Docker.
- Added shared `lib.secrets` redaction for configured credential values,
  bearer tokens, common secret assignments, and signed URL query parameters.
  Tool results, provider errors, and Backlot events now cross this boundary
  before persistence or display.
- Documented honest current enforcement: automated purge and self-service
  deletion are not yet certified. Deletion requires stopping active runs,
  exact-project scoping, optional export/backup, source/derivative removal,
  and a minimal hash-only audit record; provider-side deletion remains subject
  to provider terms.
