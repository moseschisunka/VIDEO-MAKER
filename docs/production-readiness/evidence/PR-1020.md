# PR-1020 — Strict voice-sample approval flags

Status: `IMPLEMENTED` locally; supported CI verification remains required.

## Finding

The voice-sample batch gate used Python truthiness for approval and required
flags. Values such as `"false"` or `1` could therefore be interpreted as an
explicit approval, allowing batch narration to start without the selected
voice sample being reviewed. This was a latent approval-bypass defect in the
voice-over path even though the normal boolean fixtures passed.

## Remediation

- Added `strict_bool()` to reject non-boolean contract values instead of
  coercing them.
- Applied strict parsing to `sample_approval_required`, `sample_required`,
  `sample_approved`, `approved`, and `user_approved` flags.
- Reject malformed approval status values and non-object project approval
  payloads before narration starts.
- Kept the existing explicit `approved`/`accepted` status contract and the
  batch-only gate semantics unchanged.

## Residual scope

This closes malformed-flag coercion in the voice-sample gate. It does not
certify live TTS providers, human audiovisual review, external observability,
deployment rollback, or `PR-11G`.

## Rollback

Revert the PR-1020 commit and its regression tests only after preserving this
finding. Do not restore truthy approval coercion in a production release.
