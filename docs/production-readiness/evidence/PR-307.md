# PR-307 — Fast preflight and deep diagnostics split

Status: **VERIFIED**

`lib/providers/preflight.py` adds a local-only `fast_preflight` with a short
TTL cache and the required status vocabulary: `configured`, `available_local`,
`degraded`, `unavailable`, `untested`, and `requires_live_probe`. It never
calls `get_status`, opens a socket, or performs npm/provider health checks.
`deep_preflight` is opt-in and bounds each live status call.

## Follow-up audit — 2026-09-12

A live capability check found that fast preflight treated local GPU tools with
empty dependency lists as locally available, while the four local video
generators' execution status required `VIDEO_GEN_LOCAL_ENABLED`, `diffusers`,
and `torch`. The quick menu therefore overstated local readiness. The base
dependency contract now supports `env-enabled:`; the four local video tools
declare that flag and both Python packages, and local diffusion declares the
packages its execution path imports. GPU tools without static dependencies
remain `untested`. The capability summary now separates dependency-ready,
unverified, live-probe-required, and known-unavailable providers. The operating
guide states that static configuration is not proof of a successful render or
output quality.

The offline QA harness also used to delete fixed prior-run directories and
always exited successfully even after recorded check failures. Each invocation
now uses a fresh output folder, preserves earlier renders, and exits nonzero
when a recorded check fails.
