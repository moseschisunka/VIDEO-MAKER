# PR-1025 — Fail closed on FFprobe and FFmpeg compose inputs

Status: `IMPLEMENTED` locally; supported CI verification remains required.

## Finding

`VideoCompose._has_audio_stream()` swallowed every FFprobe exception and
treated it as a valid no-audio source. Because `VideoCompose` did not declare
FFprobe as a dependency, an unavailable or hung probe could silently replace
real source audio with synthetic silence. Direct FFmpeg composition also
accepted malformed source intervals and ignored a requested audio path that did
not exist, risking inaccurate duration or an output that omitted the requested
voice/music track.

## Remediation

- Declare both `ffmpeg` and `ffprobe` as required VideoCompose dependencies.
- Bound audio-stream probes to 30 seconds and distinguish missing binaries,
  timeouts, and non-zero probe failures from a valid no-audio result.
- Require an explicit `audio` stream line rather than substring matching probe
  output.
- Validate and normalize finite, non-negative source intervals and positive
  speeds before any FFmpeg process is launched.
- Fail closed when a caller declares an audio source that is missing.
- Add regression coverage for stream detection, probe failures/timeouts,
  interval faults, numeric normalization, and missing audio inputs.
