# PR-1022 — Reject malformed music-decision approvals

Status: `IMPLEMENTED` locally; supported CI verification remains required.

## Finding

Proposal-stage music decisions converted `music_source_user_approved` with
Python `bool()`. A configuration value such as `"false"` was therefore
recorded as `user_approved: true` in the decision log, weakening the audit
record even though later immutable stage approvals still exist.

## Remediation

- Require `append_music_decision()` to receive a real boolean for
  `user_approved` and raise `MusicContractError` for strings, integers, or
  null values.
- Pass the raw configuration value from `project_pipeline` so malformed input
  cannot be silently converted before the contract sees it.
- Add regression coverage for all common truthy/falsy non-boolean forms.
