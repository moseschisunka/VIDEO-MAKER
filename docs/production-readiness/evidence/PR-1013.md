# PR-1013 — Report truthful library work-order state and progress

Status: **VERIFIED (supported CI, local source, and read-only browser
evidence)**

## Finding

The production library card used a hard-coded six-stage denominator and a
placeholder fallback that labelled a newly persisted `queued` agent handoff as
`AWAITING RENDER`. A queued work order with no checkpoints therefore appeared
as **17% Completed**, while the card ignored the manifest's actual stage count.
That was a user-facing precision fault: it could make an agent handoff look
like rendering had started and could report the wrong completion percentage.

Baseline observation was made on the local Backlot server at
`http://127.0.0.1:4750/` from source checkpoint `3a9cccb`. The existing
`WHAT IS EPIDEMIOLOGY` talking-head project had a persisted `queued` work order
and no checkpoints; the library showed `AWAITING RENDER` and `17% Completed`.

## Implementation

- Added `projectStageCount(project)` to derive the progress denominator from
  the project's manifest-backed `stage_states` rail.
- Added bounded `projectProgress(project)` clamping and a legacy-render fallback
  that only treats an observed render as complete when no checkpoint rail is
  available; queued/handoff-only projects remain at zero.
- Added `projectPlaceholderLabel(project)` for queued, running/revising,
  approval, blocked, failed, cancelled, and completed work-order states.
- Removed the hard-coded `const totalStages = 6` path from
  `backlot/ui/library.js`.
- Added release-blocking static contract assertions for the new state and
  progress helpers.

Implementation checkpoint: commit `ab01bcb` (`fix(ui): report truthful library
work-order state`).
