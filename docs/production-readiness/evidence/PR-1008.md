# PR-1008 — Backup, restore, and state migration

## Status

**VERIFIED** for the local recovery contract and disposable migration drill.
Rollback/deployment drills and long-lived backup storage remain Phase 10/11
work. Production remains ineligible until `PR-11G` passes.

## Implementation

- Added [`lib/state_backup.py`](../../../lib/state_backup.py), which creates an
  atomic ZIP with a versioned SHA-256/size manifest, excludes environment and
  credential files, rejects symlinks and temporary lock files, and supports
  state-only archives.
- Restore validates every archive member before promotion, rejects absolute,
  traversal, duplicate, unexpected, and symlink members, streams into a
  disposable staging directory, validates work-order/checkpoint/run-record
  schemas and project identity, refuses existing targets by default, and
  preserves an explicitly overwritten target under `.pre-restore-*`.
- Added [`lib/state_migrations.py`](../../../lib/state_migrations.py), an
  explicit fail-closed migrator for versionless/0.8/0.9 control state. It
  covers `project.json`, `work_order.json`, current checkpoints, and run
  records; validates before and after transformation; preserves originals in
  `history/migrations/<migration-id>/`; writes atomically; rolls written files
  back on failure; and reports `DRY_RUN`, `MIGRATED`, or idempotent `NOOP`.
- Added the checked-in [`schemas/backups/backup_manifest.schema.json`](../../../schemas/backups/backup_manifest.schema.json).
- Added [`scripts/state_backup.py`](../../../scripts/state_backup.py) and the
  [`BACKUP_RESTORE_MIGRATION.md`](../../operations/BACKUP_RESTORE_MIGRATION.md)
  operator procedure. Backups are integrity checked but not encrypted; the
  runbook requires approved encrypted storage and the 180-day policy.
- Extended [`config/security_policy.yaml`](../../../config/security_policy.yaml)
  with backup format, secret, symlink, encryption, restore, and overwrite
  safeguards.

- full media backup and byte-for-byte staged restore;
- secret/`.env` and lock/temporary exclusion;
- state-only backup behavior;
- SHA-256 tamper rejection before any target directory is promoted;
- refusal to overwrite an existing project by default;
- legacy `0.9` marker/work-order/checkpoint/run migration through dry-run and
  audited atomic promotion;
- migration idempotency (`NOOP`) and unknown-version fail-closed behavior.

A compatibility check across backup, run records, stale-output recovery,
claim/resume, and project identity contracts also passed: **28 passed**.
