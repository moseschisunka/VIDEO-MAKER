# PR-1004 — Add auth, authorization, and path controls

## Status

**VERIFIED** for the local contract suite. Production remains ineligible until
the remaining Phase 10/11 gates pass, including `PR-11G`.

## Changes

- Added a Backlot HTTP guard that requires an exact `Authorization: Bearer`
  token for non-loopback bindings, uses constant-time comparison, returns
  `503` when remote authentication is not configured, and never echoes token
  material. `BACKLOT_AUTH_REQUIRED=true` can explicitly protect loopback
  deployments behind a reverse proxy.
- Updated Dockerfile and Compose health checks to forward the token from the
  runtime environment; the image does not bake a credential into an `ENV` or
  build argument. CI supplies an ephemeral test token only to the running
  container and sends it in the health request.
- Added optional `BACKLOT_PROJECT_SCOPE` authorization. It accepts exact ids,
  comma-separated ids, or trailing-`*` prefix rules; `/api/projects` filters
  unauthorized projects and all project-scoped API/UI routes deny them.
- Hardened project resolution against empty/oversized/null-byte ids, path and
  drive separators, project-root symlinks, and resolved paths outside the
  configured projects root. Media/thumb routes retain resolved containment
  checks, preventing nested symlinks from serving outside files.
- UI board routes now validate the project component, so path traversal or an
  unknown project cannot return a board shell for an arbitrary path.
- Project creation and visual-variant creation honor the configured project
  scope before writing any files.
- Added an explicit `web_boundary` policy: the Backlot app is same-origin by
  default with no credentialed CORS, state-changing requests use an
  `Authorization: Bearer` header rather than cookies, and remote request-rate
  limiting is an edge/reverse-proxy responsibility with `429` as the expected
  rejection status. The policy deliberately does not pretend that an
  in-process limiter is distributed across deployment replicas.

## Verification

Command:

```text
python -m pytest tests/contracts/test_phase10_security.py tests/backlot/test_server.py tests/contracts/test_phase10_container.py -q
```

Result: **28 passed** (93 warnings, all existing FastAPI/Starlette deprecation
warnings). The security contract covers:

- local loopback no-auth default;
- remote missing-token fail-closed behavior;
- missing, wrong, Basic, and correct bearer credentials;
- explicit loopback auth;
- exact and prefix project scopes;
- filtered project listing and denied direct state access;
- board route validation;
- project-root and media symlink rejection;
- existing media traversal/range/thumb regressions; and
- explicit same-origin/CORS, bearer-header/CSRF, and edge-rate-limit policy;
- container health checks that remain token-aware.

## Operational configuration

For a remote deployment, set a secret `BACKLOT_AUTH_TOKEN` at runtime and keep
`BACKLOT_HOST=0.0.0.0`; optionally set `BACKLOT_PROJECT_SCOPE` to the permitted
project ids/prefixes. Do not commit `.env` or pass tokens in URLs. Local
loopback development remains available without a token unless
`BACKLOT_AUTH_REQUIRED=true` is set.
