# PR-1006 — Add structured logs, metrics, and traces

## Status

**VERIFIED** for the local structured-observability contract. Long-lived
aggregation, alert thresholds, and incident drills remain later Phase 10/11
work; production remains ineligible until `PR-11G` passes.

## Changes

- Added `lib/observability.py` with bounded thread-safe counters, gauges,
  latency observations, stable project/run `trace_id` construction, opaque
  event/span ids, JSON logging, and recursive prompt/content minimization.
- Enriched `events.jsonl` with schema version, event/span ids, project/run
  correlation, and trace id while preserving the existing flat fields consumed
  by Backlot. System-owned timestamps and ids cannot be caller-spoofed.
- Added redacted JSON logging for event and provider lifecycle records. Full
  prompts, scripts, transcripts, request/response bodies, credentials, bearer
  headers, and signed URLs are omitted, hashed/length-counted, or masked.
- Instrumented tool and provider paths with event counters, duration/latency
  observations, cost totals, and provider lifecycle counters. Metrics never
  make the creative operation fail.
- Added authenticated `GET /api/metrics` for bounded operator/CI snapshots.
- Added [`config/observability.yaml`](../../../config/observability.yaml) and
  [`docs/operations/OBSERVABILITY.md`](../../operations/OBSERVABILITY.md) as
  the machine-readable and operator-facing contracts, including the failed-run
  reconstruction procedure.
