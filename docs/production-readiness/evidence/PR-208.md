# PR-208 — Concurrency and crash fault tests

Status: **VERIFIED**

## Implemented

- Final output promotion now uses a cross-thread/process lock adjacent to the
  canonical path, preventing overlapping replacements from producing a partial
  final.
- Added concurrent two-project promotion coverage and same-final race coverage.
- Added a crash/partial-candidate test proving an invalid candidate cannot
  claim or overwrite the prior final.
- Existing renderer cleanup paths remove run-scoped candidates and temporary
  workspaces after failed Remotion/FFmpeg/HyperFrames execution.

## Evidence

```text
python -m pytest -q tests/contracts/test_phase2_faults.py tests/contracts/test_phase2_stale_output.py tests/contracts/test_phase2_media_probe.py
9 passed in 2.64s
```

The race tests prove projects do not share output state, same-final promotion
is serialized, and failed/partial media leaves the prior canonical artifact
unchanged.
